# 社交媒体地理实体语义关系体系与属性体系（v3.4）

> 版本：v3.4 实体扩展版  
> 更新日期：2026-04-16  
> 适用场景：社交媒体文本地理实体抽取
> 
> **v3.4改进**：
> 1. 实体类型扩展：新增「功能实体」和「事件实体」
> 2. 属性Schema简化：删除「联动推荐」，「适合人群」「具有限制」改为开放文本

## 一、实体体系

### 1. 实体类型（6大类）—— 用于NER边界识别

#### 空间实体（4种）—— GIS标准

| 类别 | 定义 | 识别特征 |
|------|------|----------|
| **道路** | 交通通道 | 路/大道/街/巷后缀，如珞喻路、关山大道 |
| **POI** | 具体地点/机构 | 地名+功能标识，如武汉大学、某某咖啡厅 |
| **建筑物** | 建筑设施 | 楼/厦/城/汇后缀，如泛悦汇、融科天城 |
| **街区** | 地理区域 | 商圈/校区/社区/区后缀，如街道口、光谷商圈 |

#### 语义实体（2种）—— v3.4新增

| 类别 | 定义 | 识别特征 |
|------|------|----------|
| **功能** | 场所可进行的用途类型 | 功能类型词（餐饮/购物/休闲/社交/观景等）或功能描述词（咖啡厅体验、手工艺制作） |
| **事件** | 场所发生的具体事件 | 事件名称词（樱花节/封路/开业/停业等） |

**设计说明**：
- **空间实体（4种）**：GIS标准分类，用于实体对齐和地图展示
- **语义实体（2种）**：社交媒体特色，补充场所功能和事件信息
- **细分类别由数据源补充**：实体对齐时关联高德POI/OSM数据，继承其权威分类

### 2. 空间实体属性（5个，全部可选）

**设计原则**：所有属性遵循"出现才标注"原则，语料中明确出现才标注，未出现则留空不填充。

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| **类别** | 枚举 | 实体大类（用于NER边界识别） | 道路、POI、建筑物、街区 |
| **细分** | 文本（可选） | 文本中明确提及的分类 | 餐厅、商场、大学等 |
| **特征标签** | 列表（开放文本） | 实体特征描述（保留原文表达） | 氛围超好、随手拍好看、遛娃神器等 |
| **推荐指数** | 枚举 | 整体推荐程度 | 超推、推荐、一般、不推荐 |
| **情感倾向** | 枚举 | 实体整体情感印象 | 正面、中性、负面 |

## 二、关系体系（6种）

### 1. 空间基础关系（3个）—— 图谱骨架

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **位于** | A坐落于B处（空间定位/归属） | 道路/街区/行政区 | 无 |
| **包含** | A空间包含B（位于的反向） | POI/建筑物/道路 | 无 |
| **相对方位** | A和B空间邻近+相对方位关系 | 地理实体 | 距离值、方向值 |

**v3.4改进**：删除「联动推荐」属性，相对方位关系属性简化为仅「距离值」「方向值」。

### 2. 社交语义关系（1个）—— 图谱血肉

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **具有功能** | 场所可进行的功能用途 | 功能节点（9大类）或功能实体 | 时段、适合人群、具有限制、情感倾向 |

**v3.4改进**：「具有功能」的Tail可以是功能节点（枚举）或功能实体（独立抽取）。

### 3. 对比评价关系（3个）—— 特色

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **优于** | A在某方面好于B | 地理实体 | 维度（列表） |
| **相似** | A和B在某方面相似 | 地理实体 | 维度（列表） |
| **劣于** | A在某方面不如B | 地理实体 | 维度（列表） |

### 4. 事件关系（1个）

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **发生事件** | 场所发生的特定事件 | 事件节点或事件实体 | 无（属性在事件实体上） |

**v3.4改进**：「发生事件」的Tail可以是事件节点或事件实体（独立抽取，含完整属性）。

## 三、关系属性体系（v3.4精简版）

### 1. 相对方位关系属性

| 属性 | 类型 | 说明 |
|------|------|------|
| **距离值** | 枚举 | 近、中等、远 |
| **方向值** | 枚举 | 东、南、西、北、东北、西南、东侧、西侧、对面、旁边 |

**v3.4删除**：联动推荐（原true/false布尔值）—— 信息价值有限，可通过三元组关系本身隐含表达。

### 2. 具有功能关系属性（v3.4开放文本版）

| 属性 | 类型 | 说明 |
|------|------|------|
| **时段** | 文本 | 功能适用时段（周末/晚上/樱花季等） |
| **适合人群** | 文本（开放） | 功能适合人群（保留原文表达，如"带孩子来玩"、"闺蜜聚会"） |
| **具有限制** | 列表（开放） | 功能限制条件（保留原文表达，如"排队两小时"、"停车超级难"） |
| **情感倾向** | 枚举 | 正面、中性、负面 |
| **功能描述** | 文本（可选） | 当功能类型="其他"时，具体描述功能内容 |

**v3.4改进原因**：
- **适合人群**：枚举无法穷尽社交媒体的人群表达（闺蜜、同事、健身爱好者等新人群类型无法表达）
- **具有限制**：枚举丢失原文时长准确性（"排队两小时"被归一化为"排队久"，丢失具体时长信息）
- 与v3.3"特征标签开放文本"设计理念保持一致

### 3. 对比维度枚举（8个）

| 维度 | 社交媒体常见表达 |
|------|-----------------|
| **价格** | 比...贵、比...便宜、性价比高/低 |
| **环境** | 环境好很多、氛围更好 |
| **服务** | 服务态度好、服务周到 |
| **人流量** | 人太多、人少一点 |
| **品质** | 品质更好、东西质量好 |
| **交通** | 交通更方便、停车方便 |
| **口味** | 口味更好、味道不错 |
| **其他** | 无法归纳时使用，需附带"维度描述" |

## 六、设计原则

### 1. 实体完整性原则

- **空间实体**：GIS标准，用于实体对齐和地图展示
- **语义实体**：社交媒体特色，补充场所功能和事件信息
- **三元组Tail**：可以是空间实体、语义实体或预定义节点

### 2. 开放文本原则（v3.3/v3.4延续）

- **特征标签**：开放文本，保留原文表达（v3.3）
- **适合人群**：开放文本，保留原文表达（v3.4）
- **具有限制**：开放文本列表，保留原文表达（v3.4）
- **细分类别**：开放文本，权威分类由数据源补充

### 3. 可选属性原则

- 所有属性必须在原文中有依据：明确出现、暗示表达、语义推断
- **禁止幻觉**：原文没有任何依据的属性不应标注
- 模糊表达可标注但置信度标记为"low"

### 4. 外部数据补充原则

| 数据类型 | 补充来源 |
|---------|---------|
| 交通可达性 | GIS地图数据、地铁/公交API |
| 消费信息 | 大众点评、美团等商业平台 |
| 精确坐标 | GIS数据库 |
| 实体热度 | 小红书、大众点评热度数据 |
| 权威分类 | 高德POI分类体系 |
