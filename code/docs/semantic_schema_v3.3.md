> 版本：v3.3 开放特征版  
> 更新日期：2026-04-16  
> 适用场景：社交媒体文本地理实体抽取
> 
> **v3.3改进**：特征标签从强枚举改为开放文本，保留原文真实表达

## 一、实体体系

### 1. 实体类型（4大类）—— 用于NER边界识别

| 类别 | 定义 | 识别特征 |
|------|------|----------|
| **道路** | 交通通道 | 路/大道/街/巷后缀，如珞喻路、关山大道 |
| **POI** | 具体地点/机构 | 地名+功能标识，如武汉大学、某某咖啡厅 |
| **建筑物** | 建筑设施 | 楼/厦/城/汇后缀，如泛悦汇、融科天城 |
| **街区** | 地理区域 | 商圈/校区/社区/区后缀，如街道口、光谷商圈 |

**设计说明**：
- **4大类仅用于NER实体边界识别**，帮助LLM判断文本中的地理位置是否为地理实体
- **细分类别由数据源补充**：实体对齐时关联高德POI/OSM数据，继承其权威分类
- 社交媒体文本中的分类表达往往模糊，不做强制枚举约束

### 2. 实体属性（5个，全部可选）

**设计原则**：所有属性遵循"出现才标注"原则，语料中明确出现才标注，未出现则留空不填充。

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| **类别** | 枚举 | 实体大类（用于NER边界识别） | 道路、POI、建筑物、街区 |
| **细分** | 文本（可选） | 文本中明确提及的分类（非强制，数据源分类在对齐阶段补充） | 餐厅、商场、大学等 |
| **特征标签** | 列表（开放文本） | 实体特征描述（保留原文表达） | 氛围超好、随手拍好看、遛娃神器等 |
| **推荐指数** | 枚举 | 整体推荐程度 | 超推、推荐、一般、不推荐 |
| **情感倾向** | 枚举 | 实体整体情感印象 | 正面、中性、负面 |

**重要说明**：
- **类别**：4大类枚举，用于NER阶段识别实体边界
- **细分**：开放文本，仅记录文本中**明确提及**的分类词（如"这家餐厅"、"某个商场"），不做强制枚举
- 实体入库时，通过 entity_alignment 节点关联数据源，继承高德POI的权威分类

### 3. 特征标签设计（开放文本）

**v3.3改进**：特征标签采用开放文本定义，不使用预定义枚举值。

**设计原因**：
- 社交媒体特征表达多样且不断涌现新词（如：松弛感、治愈感、出片、小确幸）
- 预定义枚举无法完全覆盖所有表达方式
- 展示优先场景：保留原文真实表达更具价值

**特征标签提取原则**：
1. **语义准确**：提取原文中准确表达实体特征的自然语言
2. **保留原貌**：不做标准化归一化，保留用户真实表达风格
3. **原文依据**：所有特征必须在原文有明确或暗示依据
4. **多特征支持**：一个实体可有多个特征标签

**常见特征类型参考**（非强制约束，仅供参考）：

| 语义类型 | 参考表达（可自由使用） |
|----------|----------------------|
| 氛围情绪 | 氛围好、松弛感、治愈感、安静、私密、解压、氛围满分 |
| 拍照体验 | 出片、拍照好看、随手拍好看、适合拍照、出片率超高 |
| 风格审美 | 文艺、复古、网红、ins风、日系、韩风、极简风 |
| 知名度 | 热门、宝藏、打卡圣地、老字号、连锁 |
| 服务体验 | 服务好、服务周到、环境好、环境nice |
| 价格评价 | 不贵、平价、性价比高、亲民价格、消费不高 |
| 人群适配 | 遛娃神器、亲子友好、情侣约会首选、学生党推荐 |
| 便利性 | 交通方便、好停车、地铁直达、不用预约 |
| 时段场景 | 晚上氛围好、日落最美、周末去处、深夜食堂 |

**注**：负面评价不通过特征标签表达，而是通过：
- 推荐指数 = "不推荐"
- 情感倾向 = "负面"
- 承载活动关系的"具有限制"属性（停车难、排队久等）

## 二、关系体系（8种）

### 1. 空间基础关系（3个）—— 图谱骨架

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **位于** | A坐落于B处（空间定位/归属） | 道路/街区/行政区 | 无 |
| **包含** | A空间包含B（位于的反向） | POI/建筑物/道路 | 无 |
| **相对方位** | A和B空间邻近+相对方位关系 | 地理实体 | 距离值、方向值、联动推荐 |

### 2. 社交语义关系（1个）—— 图谱血肉

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **具有功能** | 场所可进行的功能用途 | 功能节点（9大类） | 时段、适合人群、具有限制、情感倾向 |

### 3. 对比评价关系（3个）—— 特色

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **优于** | A在某方面好于B | 地理实体 | 维度（列表） |
| **相似** | A和B在某方面相似 | 地理实体 | 维度（列表） |
| **劣于** | A在某方面不如B | 地理实体 | 维度（列表） |

### 4. 事件关系（1个）

| 关系 | 语义定义 | Tail类型 | 关系属性 |
|------|----------|----------|----------|
| **发生事件** | 场所发生的特定事件 | 事件节点 | 无（属性全部在事件节点上） |

## 三、关系属性枚举体系

### 1. 相对方位关系属性

| 属性 | 类型 | 枚举值 |
|------|------|--------|
| **距离值** | 枚举 | 近、中等、远 |
| **方向值** | 枚举 | 东、南、西、北、东北、西南、东侧、西侧、对面、旁边 |
| **联动推荐** | 布尔 | true、false |

### 2. 具有功能关系属性

| 属性 | 类型 | 枚举值 |
|------|------|--------|
| **时段** | 文本 | 周末、晚上、樱花季、春季、夏季等 |
| **适合人群** | 枚举 | 亲子/宝妈、学生党、情侣、打工人、特种兵、银发族、宠物主、独行者、团建 |
| **具有限制** | 列表 | 需预约、排队久、停车难、限流、谢绝宠物、只收现金、时间限制、人数限制、消费门槛、季节限制 |

| **功能描述** | 文本（可选） | 当功能类型="其他"时，具体描述功能内容 |

**重要说明**：当功能类型为"其他"时，必须在"功能描述"字段中说明具体功能内容。

- 示例：原文"这里可以体验手工艺制作" → tail="其他", 功能描述="手工艺体验"

## 八、设计原则

### 1. 精简原则

- **高频保留**：保留社交媒体高频表达的关系和属性
- **低频删除**：删除占比<1%的低频关系（连接、穿过等）
- **语义合并**：合并语义边界模糊的关系/属性（位于+属于、相邻+距离+方向→相对方位）
- **枚举精简**：功能节点20→9，对比维度10→7→8（v3.3新增"其他"），特征标签约16个核心词汇（v3.3改为开放文本）

### 2. 三元组范式约束

- 所有关系的Tail必须是地理实体或预定义节点
- 属性类语义不应建模为关系
- 事件节点完整承载所有属性

### 3. 可选属性原则

- 所有属性和关系必须在原文中有依据：
  - **明确出现**：原文直接表达
  - **暗示表达**：原文间接暗示
  - **语义推断**：可从语义合理推断
- **禁止幻觉**：原文没有任何依据的属性/关系不应标注
- 模糊表达可标注但置信度标记为"low"

### 4. 外部数据补充原则

以下信息应由外部数据源补充：

| 数据类型 | 补充来源 |
|---------|---------|
| 交通可达性 | GIS地图数据、地铁/公交API |
| 消费信息 | 大众点评、美团等商业平台 |
| 精确坐标 | GIS数据库 |
| 实体热度 | 小红书、大众点评热度数据 |

class RelationTypeEnum(str, Enum):
